Where the research changed the roadmap's assumptions

  • Per-agent config moved. OpenClaw 2026.9.7 uses agents.entries.<id>; agents.list is gone from the schema and default: true survives only as a legacy marker.
  • Code Mode would have bypassed the sandbox. In 2026.9.7 it defaults to "auto", the shipped catalog marks Sonnet 5.5 as preferred, and its default executor runs model-written JavaScript inside the gateway process (OpenClaw: "not a security boundary"). sandbox.mode: "all" doesn't cover it, so the config sets tools.codeMode: false.
  • Ollama's 2026 "memory leak" and "out-of-bounds read" are the same bug (CVE-2026-7482, fixed in 0.17.1). The SSRF (CVE-2026-85180) affects 0.30.0–0.33.2, and redirect hardening shipped in 0.34.2. A separate heap disclosure (CVE-2026-5757) is listed against 0.13.5 and older. Floor: 0.34.2; Homebrew ships 0.35.0.
  • OpenAI project limits only send alerts unless "Enforce a hard limit" is switched on. Anthropic workspace limits are hard (HTTP 400 when reached).
  • openclaw sandbox explain never says pass or fail, so J1 defines "clean" as specific values in its JSON output. secrets audit --check skips Keychain-backed secrets unless you also pass --allow-exec.
  • OpenClaw has no Keychain recipe. The resolver here follows its documented exec protocol. OpenClaw refuses an exec command that isn't owned by the user running it or is group- or world-writable, so /usr/bin/security can't be called directly; a happy-owned script (mode 700) wraps it.
  • The gateway is a per-user LaunchAgent, so happy must be logged in at the desktop. Every restart therefore ends with logging happy in (J3).
  • 2026.9.x turned on more than the roadmap lists: Swarm sub-agents, the operator terminal, Bonjour on macOS, silent local device pairing, host browser control and a model catalog that refreshes from the internet. The config turns all of them off.
  • Only Tailscale's open-source tailscaled runs before anyone logs in, and happy must be its "operator" for the gateway to publish its Serve route.

@@CMD

After logging happy in, but before you log in as yourself, SSH in (as tonyli) from the other device and check:

@@CMD
diskutil apfs list | grep -E 'APFS Volume Disk|Name:|FileVault:'   # the backup volume (role Backup) should show "FileVault: Yes (Unlocked)"
@@END

Record that in the execution log and add the unlock to the reboot routine. Otherwise, after the next hourly backup, System Settings › General › Time Machine shows a latest backup after the restart (tmutil latestbackup needs root and Full Disk Access).
