@@CMD
cat ~/src/happy-config/baseline/firewall-console-wave-a.txt
@@END

Each line has three results. "via proxy: refused, allowed host ok" must hold in every line: the proxy does not care whose desktop is on the screen. "direct: blocked" is LuLu's rule, and by LuLu's source it holds only while the user it recorded (happy) owns the screen: expect "NOT BLOCKED" on the admin desktop and at the login window (where macOS reports the console user as loginwindow or root). Those lines are also the probe's control: if "direct" read "blocked" on the admin desktop too, the probe would be failing for another reason and prove nothing. A line that shows the console user changing during the probe ("happy->root") was measured across two states and is ignored. The series can be repeated straight away: the "direct" tries that get through ask GitHub's API without a login, which GitHub limits to 60 requests an hour for one address, and when that answer fails gog asks GitHub's release page instead, so a used-up limit does not by itself turn "NOT BLOCKED" into "blocked".

Done whenevery line says "control: curl ok" and "via proxy: refused, allowed host ok"; there are at least two lines with console user happy and each of them also says "direct: blocked"; and Claude has written into the execution log what "direct" said on the admin desktop and at the login window. If the admin-desktop lines also read "direct: blocked", stop and find out why before trusting any of it: by LuLu's source they should not. If any line says "NOT REFUSED" or "ALLOWED HOST NOT REACHED", or a console user happy line says "NOT BLOCKED", the gate has failed: stop, and do not start phase E.
