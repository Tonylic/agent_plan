Then prove it in happy's Terminal, before any sign-in exists:

@@CMD

@@END

A rule that allowed gog to reach Google's hosts by name cannot be written. macOS gives a firewall the host name only for connections made through its name-based networking APIs, and gog, a Go program, connects to numeric addresses; LuLu's own page says host-name rules apply only to those APIs. A rule of "any address, any port" needs no name, and LuLu keys it to gog's Developer ID signature, so it follows the program wherever it is started from and should survive an upgrade ("After wave A" re-checks that). Connections to this Mac itself are let through before rules are consulted (Allow Localhost Traffic), which is how gog will reach the proxy in B6. The probe starts a bare gog, with no proxy and an empty folder of its own, and has it try GitHub (gog update status); curl to GitHub is the control that the network is up. The wrapper itself has no way to leave the proxy out.

The proxy is tinyproxy, listening on 127.0.0.1:8877 only. It opens HTTPS tunnels (port 443) to the three hosts in egress/allow-hosts, which are Google's sign-in token endpoint, the Gmail API, and the endpoint gog falls back to for the signed-in address. Every other host gets "403 Filtered". No wildcard. The wrapper bin/happy-gog sets HTTPS_PROXY for every gog it starts, gog's source shows that each of its requests honours that variable, and Go has no direct fallback when a proxy is set. The proxy keeps its own log of every tunnel it opened and every host it refused, by name; that log is the record the catalog asks for. That tinyproxy's host filter covers HTTPS tunnels is in its source, not its manual, which is why this step tests a refused host and an allowed one. If macOS asks whether tinyproxy may accept incoming network connections, answer Deny: it listens on this Mac only.
